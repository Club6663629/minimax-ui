HIBTV · SCRIPT TO EPISODE · V1 定稿

把已经写好的剧本，
直接拍成一集短剧

不改编、不重写。上传剧本与美术设定，hibtv 只做一件事：把已经定稿的字，拆成能开工的资产——大纲、角色卡、场景与道具、一集一页的节拍表、一段一页的镜头卡，最后按段拼成片。每一步都能改、能撤销、能只重跑那一小块。

相对截图的 3 处设计变更

这 3 处是设计主张，其余按截图复刻
#截图里的做法现在的做法为什么
1 新建小说项目
单文件上传小说
改编幅度（忠实 / 抽桷）
必留角色与戏份		 新建短剧项目
双上传：剧本（必填）+ 美术设定（必填）
删除改编幅度与必留角色
新增：项目名 / 题材 / 总集数 / 单集时长 / 画面比例（默认 9:16）/ 必须保留的名场面（可选）
模型固定：deepseek · Qwen-Image · Minimax-h3，只展示不可改
自动识别：集数 · 每集场次 · 台词条数 · 角色·场景·道具条目数 · 付费卡点		 剧本已经定稿，输入物本身就是两份生产资料。改编类字段没有语义，留着会让人误以为能改戏。美术设定是出图与出片的硬依赖，必须是必填项而不是附件。
2 大纲含「改编取舍」
保留 / 砍掉 / 合并 / 风险		 去掉改编取舍，改为 8 子页：内核 / 人物关系 / 角色表 / 场景表 / 道具表 / 分集 / 卡点 / 对齐检查（新增）
对齐检查 = 剧本里出现的人、场景、道具、特效，美术设定是否都有对应条目；缺项一键"补建到美术"		 不改编就没有取舍可写。真正会卡住下游的是"剧本写了、美术没给"的缺口——它今天要靠人眼看，做成一张覆盖率表后才能一键补齐，出图才不会在第 6 集停住。
3 下游 5 页（角色 / 美术 / 剧本 / 分镜 / 出视频） 全部保留并按截图复刻：锚点派生与改图、场景道具多视角、一集一页节拍表、一段一页一镜一卡、整集成片与时间轴、右侧监看、重新生成、撤销与变更记录 这 5 页是产品的实际工作区，改动只会带来学习成本。唯一补充的是把"过期 / 待确认 / 版本"这三件状态说清楚，避免下游静默用旧图。

截图里是“视频导引 / 旧版布局”，产品里按下面方式落地
#截图 / 旧实现现在的做法为什么
4 底部贯穿七步的 banner
导入小说 → 写大纲 → 角色、美术、剧本 → 分镜 → 出视频		 产品内整条删除：它是视频里的导引字卡，不是界面元素。原型里 STEPS / stepsHTML() / 底部 <footer class="steps"> 已全部移除 产品里常驻一条不能点的“流程”只会占地方、还会让人以为必须按顺序走。页面导改由左侧 rail 与页内动作按钮完成。
5 首页照搬宣传页：产品主张 + 大输入框 + 上传 + 从模板开始 + 最近项目 项目列表页：一行一个项目（进度 / 资产数 / 最后编辑），一张新建卡；第一版只支持上传剧本 + 美术设定；模板库、对话建项、从小说改编均删除 工作台首页只回答两件事：去哪个项目、怎么建一个新项目。把营销位置让给项目列表，日常用起来才快。
6 模型展示为 deepseek-v4-pro，旁边带「更改」；下游还混着 Wan / Seedance / H3 统一为 deepseek（文本）· Qwen-Image（图片）· Minimax-h3（视频）；所有「更改」入口与下拉全部去掉，只保留只读 chip + “模型服务固定，不可更改” 第一版不开放模型选择：用户选了也改不了出图质量，反而多一层错预期。固定模型能把“出图不稳定”归因到提示词与参考图。
7 角色 / 场景卡只有“改图 / 放大”，没有上传、删除，也没有大图四视图 角色、场景、道具三类卡统一为：左锚点大图 + 右多视图竖列 + 提示词与图上四个图标（重新生成 / 改图 / 上传 / 删除，另加常驻的提示词修改链接）；点图片弹四视图（场景道具为全部视图） 卡上直接给齐“改字、重出、上传真图、删掉”四条路，才不用为了换一张图去别的页。大图四视图是为了同时看住脸与侧面、背面是否走形。

交付前定稿的 3 处

跟着原型一起收口的细节
#上一版定稿做法为什么
8 按钮说明用伪元素画在图片框内，被 overflow:hidden 裁掉 改为真实 <span class="tip"> 放到图片框外，浮在按钮上方；四张卡右边缘对齐按钮组，宽 170px 不越出卡片；命中区用 .ic::after 外扩到 32×30 盖住 5px 间隙，并去掉锚点上的原生 title “字出不来”与“触发慢”是同一个坑的两半：一个是被裁，一个是要精确对准 26px 小方块、还要等 1s 系统灰提示
9 镜卡里已加的引用素材是一排文字 chip 改为小缩略图 34×34 + 左上角标 + 图下一行素材名（过长省略），末位虚线「＋ 加素材」；右栏同步「类型 / 名称 / 角标 / 缩略图 / 备注框」 发片前要能一眼确认“发给模型的是哪张图”，文字 chip 看不到画面，也分不清同一场景的不同视角
10 段长按 15s 算：22 段合计 321.9s（5:22），还标了 26 镜超范围 统一按视频模型单次上限段 ≤ 13 秒重算：22 段 / 64 镜 / 276.0s = 4:36，均镜长 4.3s，超段 0，成片 150.6 MB 段长是模型能力边界，不是排版偏好；先定上限再排镜，才不会到出片阶段才被打回重分
05

素材替换位

改图不改代码
路图片路径约定

所有图片位都有固定路径，文件不存在时自动降级为同风格占位卡（暗金渐变 + 名称 + 视角标签）：

  • 角色锚点 assets/cast/<ID>-front.jpg，派生 -big / -side / -back
  • 场景 assets/scene/<S01…>-front.jpg，派生 -top / -back / -left / -right
  • 道具 assets/prop/<P01…>-front.jpg
  • 成片与分镜图 assets/frame/E01-master.jpg、E01-07-1.jpg、E01-07-video.jpg

不想放文件也行：角色 / 场景 / 道具卡上都有「上传」，选的图会直接顶掉该条目的正面锚点（只存在当前页面内存里，刷新即还原）。

开怎么开启真图

默认不发图片请求（这样占位图缺失时控制台是干净的）。两种开启方式，二选一：

  • 地址加参数：prototype.html?assets=1
  • 在本目录建 assets/manifest.json（内容可为 {}），用 http(s) 打开时原型探测到即自动挂图

注：file:// 下浏览器禁止探测本地文件，请用 ?assets=1 方式（或起一个本地静态服务）。http(s) 下若没建 manifest，控制台会有一条 assets/manifest.json 的 404，属预期探测。

建议尺寸：竖屏 720×1280（或 1080×1920），横屏 1280×720。图片只是占位与对齐用，真实生成走模型，不在此列。

06

自检结论

对照验收口径逐条跑过
✓七步主链路每步 ≥ 3 个可点交互，且都有反馈（toast / 进度 / 版本 / 撤销）
✓13 条路由（home / outline 8 子页 / cast / art / script×10 / storyboard 3 层 / video / overview / changes / assets / settings）全部可渲染，无 JS 异常
✓空态 / 生成中 / 完成三态齐备：角色空态 → 生成角色卡 → 出图 → 待确认
✓9:16 ↔ 16:9 往返切换不破版：无横向滚动、卡片与右侧面板不重叠
✓file:// 直开可用，无外部请求（图片默认走占位层）
✓三处变更可被一眼指出：双上传、无改编幅度、大纲无改编取舍且新增对齐检查
✓产品内无底部流程条；首页是项目列表 + 新建入口，只有“剧本 + 美术设定”一条建项路径，找不到模板入口
✓模型全局统一为 deepseek / Qwen-Image / Minimax-h3，页面上没有任何「更改」或模型下拉
✓角色 / 场景 / 道具卡：鼠标移到图上浮现四个图标（重新生成 / 改图 / 上传 / 删除），hover 图标后按钮上方浮出说明卡（金色动作名 + 一句话），提示词另有常驻「修改」链接；点图片看四视图
✓撤销闭环：双击改单元格 → toast「已改 1 处 · 撤销」→ 撤销后原值回写
✓版本闭环：段重跑 → v2 出现 → 可回切 v1；整集重新合成 → v3
未实测项（本原型刻意不做）：真实模型出图与出片的质量与时延、并发排队与计费、多人协作冲突合并、真实剧本解析器的语义准确率、跨集台词一致性与音色对齐。这些在 PRD 第 12 章列为待验证。
07

假设与不做

假演示数据

沿用截图项目骨架并整体换语义：项目《上门龙婿》10 集 × 2–5 分钟，15 角色 / 8 场景 / 4 道具 / 5 处卡点，第 1 集 22 段 64 镜 4:36。所有数字均为演示样本，页面上标注来源。

不不做后端

不接真实模型、不生成真实视频，所有"生成"是前端定时器模拟；不做登录、团队协作、计费。生成队列 / 资产库 / 设置是可打开但内容收敛的抽屉页。

占占位图策略

不做 AI 生成的示意图，只留标准尺寸与替换路径；占位按类型（人 / 场景 / 道具 / 视频帧）给不同轮廓，便于在视觉上区分资产种类。
