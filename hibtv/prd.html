hibtv：把定稿的剧本，拆成能开工的资产

hibtv 是一条从「已经写完的剧本」到「一集成片」的生产线。它不做小说改编、不重写台词、不替编剧做取舍；它只把文字里的信息解析成结构化资产（大纲 / 角色 / 场景 / 道具 / 节拍 / 镜头 / 参考素材），每一步都可编辑、可撤销、可只重跑出错的那一小块，最后按段拼成片。

01

背景与目标

为什么不做「小说改编」

现状问题

短剧团队真正的瓶颈不在「写」，而在「拆」：一个已经定稿的剧本，要拆成分集钩子、角色与场景清单、服装与道具、每集 20 拍左右的节拍、22 段左右的镜头、每一镜的参考图和视频提示词。这些工作现在散在文档、表格、群聊和出图工具里，改一句台词要人工回溯五六处，谁改的、改到哪一步、下游哪张图过期了，全靠记忆。

  • 一致性靠人盯：同一角色在 15 张图里长得不一样，因为没有一个「锚点图」被当成唯一真相。
  • 返工成本高：改一个角色的服装描述，理论上要重出 4 张锚点 + 3 张派生 + 引用到他的每一镜参考图；实际做法往往是「先这样吧」。
  • 进度不可见：10 集里哪几集有分镜、哪几段有片、哪一版是当前版，需要问人。
  • 工具链割裂：剧本在飞书、参考图在网盘、提示词在另一个表格，谁都不敢删任何一份。

产品目标

目标做法可验证的结果
把剧本变成结构化资产双上传（剧本 + 美术设定）→ 自动识别集 / 场 / 台词 / 角色 / 场景 / 道具条目 → 落到 8 张表上传后 1 屏内能看到「10 集 · 30 场 · 1,024 条台词 · 15 角色 / 8 场景 / 4 道具」 演示数据
一致性有唯一真相每个角色一张「正面全身锚点」，其余视图都是它的派生；改锚点即标记派生过期15 人 × 4 张 = 60 张图，全部挂在锚点下 设计假设
改动可追溯、可撤销任何字段改动写入变更日志（谁 / 何时 / 改了什么），支持单条撤销双击改一格 → 左下 toast 带「撤销」
只重跑坏掉的那一块段级重写、单图重出、单段重出片、整集重合成「按要求重写本段」只改本段镜头提示词
进度一眼可见项目列表页的状态行 + 概览页状态表 + 生成队列抽屉不靠底部流程条：进程写在项目行与概览页里

非目标

  • 不做小说改编、不做剧本创作、不做 AI 续写台词——输入必须是已经定稿的剧本。
  • 不在本版本做团队协作、评论、审批流、计费。
  • 不替用户决定「删哪场、加哪场」；「必须保留的名场面」只做保护，不做取舍。
一句话判断标准：任何一屏上，用户都应该能回答「现在这版是哪一版、它上游是什么、改了会影响谁」。

三个角色，一条产线

三个入口场景

A. 新项目冷启动

剧本和美术设定都已定稿，从零开始。
路径：新建短剧项目 → 双上传 → 解析 → 大纲 → 角色 → 美术 → 剧本 → 分镜 → 出视频。

B. 半途接手

项目已跑到第 3 集，接手的人要判断「哪些可信」。
路径：概览 → 变更页看最近改动 → 大纲「对齐检查」补缺项 → 分镜总表看断点。

C. 局部返工

第 1 集第 7 段的表演不对，其余都过。
路径：分镜 → 一段一页 → 按要求重写本段 → 重新生成视频 → 版本 2 → 整集重合成。

D. 一致性修复

角色 C01 的服装描述写错了，已经出了 4 张图。
路径：角色 → 改图（一句话要求）→ 锚点变「待确认」、3 张派生打过期 → 接受 v2。

关键约束

  • 桌面宽 ≥ 1280：四区布局（rail 58 + 侧栏 236 + 主区 + 右面板 326）在这个宽度下才成立；窄屏只保证不破版，不做移动端重排。
  • 一屏一决策：任何页面不出现两个同等重要的主按钮；主按钮永远在右上或段内右下。
  • 不静默重跑：上游改动只标记下游过期，绝不自动重跑（省钱、也避免"我还没看完就被覆盖"）。
03

产品定位与边界

做什么 / 不做什么

定位

hibtv = 短剧的资产层 + 生产编排层。它不生产创意，它把创意变成可排期、可分配、可返工的资产；它也不替模型出图，它负责「什么时候、用哪张参考图、发给哪个模型、出几版、哪版算数」。

输入剧本 + 美术设定› 资产大纲 / 角色 / 场景 / 道具› 编排节拍 / 段 / 镜› 产出段片 → 集成片

边界表

能力V1 之内V1 之外
输入上传剧本（.md/.txt/.docx）+ 美术设定；自动识别集 / 场 / 台词 / 条目小说原文、分镜脚本、PDF 扫描件
大纲内核 / 人物关系 / 角色表 / 场景表 / 道具表 / 分集 / 卡点 / 对齐检查改编取舍、剧情改写建议、平台的「爽点打分」
角色 · 美术锚点 + 派生多视角、提示词、音色、朝代总设定、改图与版本3D 模型、绑定、口型驱动
剧本一集一页节拍表、每拍秒数、站位、表演提示、钩子与断点剧本编辑器（不提供创作态编辑，只做就地微调）
分镜总表 / 本集段表 / 一段一页一镜一卡、视频提示词、引用素材、监看手绘分镜板、动态分镜预览（animatic）

商业化—计费、额度、套餐
明确不做的三件事：① 不需要用户写提示词——提示词由资产与镜卡自动拼装，用户只写「一句话要求」；② 不允许「跳过一致性」——每张图必须挂锚点或明确标「独立参考」；③ 不覆盖历史——任何重出都是新增版本，旧版永远可切回。

导航原则

  • 三种进入方式并行：rail（按模块）、页内链接（看大纲 / 看分镜 / 看素材）、项目列表——不强迫走线性流程；没有底部流程条。
  • 切页不丢状态：路由换视图，数据在内存里；切页回来仍是你离开时的那一集那一段。
  • 面包屑只到二级：三段以内（工作台 › 项目 › 页），再深的信息交给页面标题。

P0 首页 #/home

P1 项目初始化 弹窗 → 进度 → 大纲

  • 拖入即识别：两个文件都上传后，上传区下方出现一行灰字规模摘要（10 集 · 30 场 · 1,024 条台词 · 15 角色 / 8 场景 / 4 道具 · 3 类特效 · 5 处付费卡点）；字段变为「已自动识别」，可手改。演示数据
  • 三段进度：剧本解析 → 美术设定解析 → 大纲骨架；每段有独立状态（等待 / 进行 / 完成）与百分比，完成后打勾。
  • 取消生成：任何阶段都能取消；取消后直接以已有结果进入大纲（不空手而归）。
  • 自动跳转：三段全绿后 1.2s 自动进大纲内核页。
反例约束：不允许在解析期间进入下游页面并显示空表——下游在解析完成前只给骨架占位，不给假数据。

P5 剧本 #/script/<ep>

  • 左列集列表：每集 4 个数字（时长 / 场 / 拍 / 台词）+ 偏差 % + 钩子 / 断点 / 爽点摘要，一眼看出哪集写超了。

生成队列规则

  • 单一队列：所有生成任务进同一个队列（出图、出分镜、出段片、合成），抽屉里只按到达顺序列，不做优先级抢占。
  • 不阻塞 UI：入队后用户可以继续改上游；改上游会让队列里的任务标「参数已过期，建议重排」。
  • 耗时预估：出图按张数、出片按秒数估；原型里的「约 18 分钟 / 约 12 分钟」是设计假设，不是实测。设计假设
  • 失败处理：单张失败只标该张「重试」，不整批失败；整批失败保留已成功的那部分。
  • 关闭页面：真实产品里任务继续（服务端）；原型的定时器随页面结束，已在交互规格里注明。
重要取舍：本版本不做「上游改动自动触发下游重跑」。原因是短剧里一次改台词可能连带 8 张图、2 段片，自动重跑会烧掉额度并且覆盖用户还没看过的结果。改为「标过期 + 用户一键重跑」。

编辑 · 撤销 · 过期传播

三条规则撑起「敢改」

规则一：一切编辑走同一套入口

  • 可编辑元素带 data-edit="字段路径"；双击进入 contenteditable。
  • Enter 保存、Esc 取消、Shift+Enter 换行；失焦等同保存。
  • 保存时写一条 Change（who=你 / at=现在 / what=表名 · 行标识 · 字段 / from / to），并弹 toast「已改 1 处 · 撤销」（7s 内有效）。
  • 变更页可对任意一条点「撤销」：回写旧值 + 记录标 undone + 重渲染当前页。

规则二：撤销只回写，不连带回滚下游

撤销一个字段不会自动把下游的图片 / 段片退回上一版，因为下游可能已经被用户手动重出过。撤销只做两件事：值回到旧值、把受影响的下游重新标记为「过期」。是否重跑仍由用户决定。

规则三：过期传播按「引用关系」而不是「页面层级」

上游改动自动标过期的下游不标过期的
角色提示词 / 锚点改图该角色的 3 张派生图；引用该角色的镜卡参考图（标提示，不删）已经出好的段片（只提示「参考已更新」，等用户重出）
场景正面锚点改图该场景的 4 张派生其他场景
朝代设定全部美术图（场景 + 道具）角色提示词（只标「建议同步」）
节拍台词 / 表演提示本段镜卡的视频提示词角色资产
段长上限超长的段（标「超段 N s」）已出片的段（保留但提示重排）
视觉语言只有两种：红色斜纹遮罩 = 已过期，不可用于下次生成；红 / 金 chip「待确认」 = 已出新版但用户还没接受。其他状态一律用中性灰，避免"到处都是红"。
